Guiding a complex chemical test from setup to result

UR2 TestKit is a mobile-first product that connects a field user, laboratory hardware, and a computer-vision analysis pipeline. I translated a multi-stage physical procedure into a six-step experience with clear progress, timed states, image capture, and readable results.

Role Frontend & UX Engineer
Organization Garg Group, UIUC
Timeline May 2026 – Present
Tools Figma, React, Flask, OpenCV
01 · Context

The interface had to coordinate people, chemistry, and hardware

The underlying analysis combines sample preparation, reagent confirmation, a timed reaction, camera capture, and computer-vision calculations. The software needed to preserve that order while remaining usable on a phone in a field or laboratory setting.

My responsibility was to turn the scientific requirements into a coherent interface, prototype the workflow, and implement the responsive product that connects to the analysis pipeline.

Design challenge: How might we make every required action and system state visible without asking users to understand the underlying hardware and image-processing architecture?
02 · Workflow

One guided sequence instead of a collection of disconnected controls

I mapped the procedure into a stepper that keeps the current action prominent and makes progress visible. The complete flow covers sample identification, preparation checks, the reaction timer, image capture, processing, and results.

1

Identify

Enter the sample identifier and establish the record for the test.

2

Prepare

Confirm reagents and required setup before the timed portion begins.

3

Capture

Complete the 180-second reaction and capture the sample image.

4

Interpret

Process the image and present the resulting material concentrations.

03 · Decisions

Design choices that support a physical, time-sensitive task

Progressive guidance

The stepper exposes only the information needed for the current stage while preserving an overview of progress.

Visible system status

Timers, camera states, processing feedback, and result gauges communicate what the device is doing.

Reusable visual language

CSS tokens, dark mode, SVG gauges, and microinteractions create consistency across mobile screens.

04 · Delivery

Prototyping and implementation stayed connected

I implemented the experience as a responsive React PWA and connected it to a Flask service that passes captured images to the Python/OpenCV analysis pipeline. Local storage preserves settings and test history, while the interface provides a software fallback for development when physical hardware is unavailable.

The result is a working end-to-end workflow rather than a standalone mockup. Designing and building the interface together allowed interaction details to be evaluated against the real timing, camera, and processing constraints.

05 · Validation

What is complete—and what still needs evidence

The six-step PWA and analysis integration are implemented. Formal usability results are not yet included here, so I do not claim improvements in completion rate or testing time.

The next validation cycle should measure test completion, time per step, setup errors, recovery from camera failures, and comprehension of the final result. Those observations would inform whether the sequence, labels, and feedback states need further iteration.

Reflection: Interfaces for physical workflows must make the system's state as legible as the user's next action. The best visual treatment cannot compensate for hidden timing, hardware, or recovery states.
